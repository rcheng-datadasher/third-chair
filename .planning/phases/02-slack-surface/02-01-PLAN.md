## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Slack workspace to Bolt (Socket Mode) | Message text, user ids and shortcut/command payloads from any channel member are untrusted input |
| Bolt to Postgres (via dispatchAgentRun) | Only messages that survive the first-statement guard cross into the agent and the database |
| Bolt to console log | Log lines are persisted in terminal scrollback and /tmp; conversation content must not leak there |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Spoofing | Socket Mode event and interactivity payloads | low | accept | Bolt's Socket Mode client authenticates with the app-level token over an outbound WebSocket; there is no public HTTP endpoint and no request-signature code to write |
| T-02-02 | Tampering | handleWatchedChannelMessage (bot feedback loop, other bots' posts, edits) | medium | mitigate | The first-statement guard drops a defined subtype, a bot_id, empty text and non-allowlisted channels before any log or dispatch; Bolt's ignoreSelf default already drops the bot's own posts |
| T-02-03 | Information disclosure | reached-handler log lines | medium | mitigate | Log lines carry event_id/trigger_id, channel, ts and user id only, never message text; dropped messages produce no log line at all |
| T-02-04 | Denial of service | Slack retries after a late ack producing duplicate cards | medium | mitigate | `await ack()` is the first awaited statement in every interactive handler (grep gate); the unique Proposal.dedupe_key turns any redelivered dispatch into a `duplicate dispatch skipped` no-op in dispatchSlackMessage |
| T-02-05 | Tampering | handleExtractShortcut run on a bot-authored message or the bot's own card | medium | mitigate | The handler returns before dispatch when the target message has no human user id or carries a bot_id |
