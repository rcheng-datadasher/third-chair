<objective>
Deliver CAL-02..05 on top of 03-01's client. `createCalendarEvent` inserts a real event for a Proposal with a Meet link, invites the participants, uses a deterministic base32hex id, treats a repeat insert's 409 as success via `events.get`, and tags the event for demo cleanup.

- **FA-2 (research A1):** a duplicate-id insert against a previously cancelled event is assumed to still return 409. If Google instead inserts fresh, the `CancelledEventError` guard is simply never reached; either way no dead event is returned as success.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07 | Information Disclosure | `createCalendarEvent` and `smoke.ts` error logging | high | mitigate | Logs print ids, links, statuses and messages only, never an error object or credential. The smoke `[smoke] FAILED` handler from 03-01 prints status and message only |
| T-03-08 | Elevation of Privilege | organizer resolution in `createCalendarEvent` | high | mitigate | `MissingOrganizerError` before any Google call when no organizer resolves. The token is read only for the resolved organizer's own row via `getCalendarClient`, and production code never picks "any user with a token" (only the manual smoke script selects A) |
| T-03-09 | Tampering | 409 fallback returning a cancelled event as success | medium | mitigate | Check `status === "cancelled"` after `events.get` and throw `CancelledEventError` |
| T-03-10 | Denial of Service | self-inflicted quota use and invite spam on retries | medium | mitigate | No retry loops. The 409 path makes exactly one `events.get` and never re-inserts or updates, so no repeat invitation email |
| T-03-11 | Information Disclosure | invitations sent to the wrong recipients | medium | mitigate | Attendees come only from this proposal's Participant emails (deduplicated), with no hardcoded or config-supplied addresses |
| T-03-12 | Spoofing | deterministic, guessable event id | low | accept | The id is an idempotency key, not a secret; event access is governed by Google Calendar ACLs |
| T-03-13 | Information Disclosure | refresh token plaintext at rest | medium | accept | Inherited Phase 1 debt (one-laptop demo); this plan only reads it |

No package installs in this plan (`node:crypto` is stdlib; googleapis was installed in Phase 1), so no supply-chain row applies.
</threat_model>
