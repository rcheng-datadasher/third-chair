## Flagged assumptions

- ActionItem `kind`/`state` values mirror `prisma/seed.ts` or the schema enum. If they are free strings, `meeting`/`pending` is used.
- Participants without a User row get no ActionItem. In the two-user demo, author B always has one.
- Two concurrent deliveries of one message can both pass the Decision pre-check and double-write an ignored Decision. This is accepted with a `ponytail:` comment; the upgrade is a unique `(team_id, source_channel, source_ts)` on Decision.
- If the model returns a different start on a retry, the dedupe_key differs and a second Proposal can appear. Accepted: Trigger.dev's idempotency key (AGT-11) already suppresses duplicate task runs.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Slack/Trigger.dev redelivery → runAgent | The same message can arrive more than once |
| Model-named participants → ActionItem/Participant rows | Model output decides who gets per-user rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-08 | Denial of Service | runAgent redelivery | medium | mitigate | Decision pre-check returns the finished run without a model call; P2002 on dedupe_key reuses the existing row, and the card posts only when card_ts is null. |
| T-05-09 | Spoofing | proposeNode ActionItem creation | high | mitigate | ActionItems are created only for participants that passed 05-01's author-plus-literal-mention filter and that have a User row in the same team_id, so a model-invented id never gets a per-user row. |
| T-05-10 | Repudiation | runAgent replay path | low | mitigate | decision.create remains the single write site (grep count gate). Replays return the existing Decision id instead of adding rows. |
| T-05-11 | Tampering | concurrent redelivery race | low | accept | Two deliveries within the same moment can double-write an ignored Decision. The demo has one watched channel, and the ceiling is documented in a ponytail: comment. |
</threat_model>
