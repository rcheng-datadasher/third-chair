Step 1, utils/time.ts. Append; never fork Phase 1's formatter (Phase 1 D-08).
- Exported const tuple `WEEKDAYS`: lowercase sunday through saturday.
- Type `Weekday`.
- Type `WhenHint = { weekday: Weekday | null; day_offset: number | null; time_of_day: string | null }`.
- `hktDateParts(now: Date): { isoDate: string; weekday: Weekday; time: string }`: one Intl.DateTimeFormat with locale en-CA, timeZone Asia/Hong_Kong, weekday long, 2-digit month/day, hour and minute, hourCycle h23.
- `resolveStartIso(now: Date, hint: WhenHint): string`, rule per D-12/D-13:
  - Take today's HKT calendar date and weekday from hktDateParts.
  - Days to add: when weekday is set, (targetIndex − todayIndex + 7) % 7, with 0 becoming 7 ("next Friday" never means today). Otherwise day_offset, defaulting to 1.
  - Build the target date with Date.UTC(year, month − 1, day + days) and take YYYY-MM-DD from its toISOString.
  - Time is time_of_day, defaulting to 10:00.
  - Return date + "T" + time + ":00+08:00".
- Do not copy 05-RESEARCH's resolveNextWeekday example. It reads getUTCDate from an HKT-midnight instant and returns 2026-09-17 for Saturday 12 Sep → friday; this was confirmed by direct execution during planning.
- Mark the two defaults (10:00, tomorrow) with a ponytail: comment saying the Edit & approve modal is where a human corrects them.
