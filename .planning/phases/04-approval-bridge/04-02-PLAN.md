**Phase goal (ROADMAP, verbatim):** Approving a proposal from Slack writes a real Calendar event and updates the card, with a working local/Trigger.dev transport switch.

**User story:** not framed. The ROADMAP Goal line for Phase 4 is not in "As a / I want to / so that" form, and MVP mode forbids inventing one. Surfaced to the orchestrator; run `/gsd mvp-phase 4` to author a story.

<objective>
Give the agent a second way to run. A watched-channel message reaches the same `runAgent` body either through a Trigger.dev task in its own Node process or inline in the Bolt process, decided by one environment variable and a restart. The task is a thin wrapper with no logic, the config file carries the Prisma build extension from the start, and the whole bundled chain is proven with one real run before anything is layered on it.

Decisions implemented:
- **Task and transport:** D-12 (thin wrapper in `lib/agent/tasks/`, Node runtime, cards posted through the standalone Web API client), D-13 (idempotency key from team, channel and timestamp), D-14 (the Prisma build extension present from the start, proven by a real run before it is trusted), D-15 (the transport switch lives in `dispatchAgentRun`, the Phase 1 seam), D-16 (the pinned CLI invocation and the lockfile check after the first run), D-17 (both transports hand-checked, with the inline side verified once under time pressure).
- **Ownership and rules:** D-18, D-19 (this phase owns the task directory and the config file; graph internals, `app/**` and `components/**` stay untouched), D-21 (Bolt, the Trigger.dev dev CLI and Postgres; Next.js is not needed), D-22 (shared Prisma singleton, config-module environment access with the build-file carve-out, TSDoc, Biome, no test files).

Purpose: the Trigger.dev dev CLI keeps a live dependency on a hosted control plane even for local runs, and the demo happens on venue wifi. Wiring and proving both transports now is what turns a wifi drop from a dead demo into a restart.

Output: `trigger.config.ts`, `lib/agent/tasks/run-agent.ts`, and the filled-in `trigger` branch of `lib/agent/dispatch.ts`.
</objective>
