<objective>
Make the data and configuration layer real: one typed env module, one Postgres, one schema, one client, one seeded row set, and a page that proves the whole chain by rendering a live count.

**User story (MVP mode):** **As a** developer about to fan out into parallel tracks, **I want to** have every environment key declared once, the full schema already pushed, and real rows readable through the shared Prisma client, **so that** no parallel track has to touch config or push schema during the build window.

Purpose: FND-05 through FND-08 and FND-10 are the shared substrate every later phase consumes and none may fork. D-09's "every column any core phase needs" exists precisely so no track runs a second `db push` mid-window.

Output: `docker-compose.yml`, both `.env` example files, `lib/config.ts`, `lib/db.ts`, `prisma.config.ts`, the full `prisma/schema.prisma`, `prisma/seed.ts`, and an `app/page.tsx` that renders `prisma.proposal.count()`.

This plan's own vertical proof is Task 3, the `[BLOCKING]` tracer: Postgres container → pushed schema → seeded rows → `lib/db.ts` singleton → Server Component → HTTP 200 carrying a real number. The phase's full end-to-end tracer is the SLK-07 round trip in `01-03-PLAN.md`.
</objective>
