## Flagged assumptions

- **FA-1 (07-RESEARCH Pitfall 1 / A2, the one item that can silently kill the demo):** Phase 5's `DEFAULT_DURATION_MINUTES` is 30, so a 10:30 ask with no stated duration resolves to 10:30-11:00 and does **not** overlap an 11:00 event under the correct half-open rule. The seed wording therefore states a duration explicitly. Task 1's triage step checks the extracted `duration_minutes` on the row before anyone suspects the overlap code.
- **FA-2:** the calendar owner is resolved as the team's single user with a non-null `google_refresh_token` (user A — only A has Google consent, PROJECT.md Constraints). Multi-organizer resolution is out of scope and gets a `ponytail:` comment.
- **FA-3:** a `freebusy.query` failure is logged loudly and the run continues on pending Proposals alone, so the demo path never dies on a calendar outage. This is a deliberate shortcut for the window; recorded as a known shortcut for Phase 11's `/ponytail-debt` section.
- **FA-4 (07-RESEARCH Pitfall 5):** pending Proposals that already carry `alternatives` are excluded from the busy union, so a conflict card's own pending row does not pollute later checks. Chosen over a schema change, which D-03/PROJECT.md's parallelism rules make expensive this late.

- **FA-6:** 05-03 (the medium-confidence "Edit & approve" card variant) may or may not have shipped. If it did, a clash takes precedence over the edit variant — the conflict card carries Approve and Reject anyway, so nothing is lost.
