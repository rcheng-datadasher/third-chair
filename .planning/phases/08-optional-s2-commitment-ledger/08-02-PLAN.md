## Phase Goal

**MVP note (MVP_MODE=true):** Phase 8's ROADMAP `**Goal:**` line — *"A CopilotKit surface renders a heterogeneous commitment ledger, proving generative UI"* — is not in `As a / I want to / so that` form. No user story is invented here. Run `/gsd mvp-phase 08` if one is wanted.

<objective>
Turn 08-01's proven round trip into the actual generative-UI beat: four visibly different components, chosen deterministically per row, plus the nudge that routes through the existing Slack approval card.

This is STR-05's demonstrable half and the phase's exit criterion (D-10): ask two different commitment-shaped questions, see two visibly different components. 08-01 already guarantees that outcome by data shape — the seeded rows cover all four kinds and the `owed_by_me` and `owed_to_me` filters produce disjoint sets — so this plan is rendering work, not risk work. The one genuinely new risk is the nudge, and it is contained: a nudge writes a real `Proposal` row and calls the existing `postProposalCard`, touching nothing inside `lib/slack/**`.

Runs alongside nothing (D-04), after 08-01 in wave 2, single executor. The abandon clock is still running: if at least two different component types are not rendering by 14:40 HKT, do not merge and stop (D-02). Impeccable is dropped unless the phase is ahead of schedule (D-22).

Purpose: the point of generative UI is that the shape of the answer is not known in advance. If every answer is the same row, it is a table, not generative UI — so the four components must look genuinely different from one another, not four skins of one list item.

Output: a fan-out component, four presentational components, the nudge domain module and its thin route.
</objective>
