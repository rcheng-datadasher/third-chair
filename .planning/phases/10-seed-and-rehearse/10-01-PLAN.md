# Phase 10 Plan 01: Idempotent demo reset script

<objective>
Create `prisma/reset-demo.ts`, the one code file Phase 10 owns (D-02). Per the D-03 split, this plan is the reset script, and 10-02 seeds, rehearses and audits. One command wipes every rehearsal trace: the demo-tagged events on organizer A's Google Calendar (D-04, CAL-05 tag) and the team's ActionItem, Participant, Decision and Proposal rows. User, Installation and Preference survive. The script is idempotent: a second back-to-back run reports zero of everything (D-05, success criterion 1).

Purpose: without it, every rehearsal adds a confirmed Proposal and a Calendar event on Fri 18 Sep 2026. Those pollute the pending-Proposal union and freebusy for the 10:30-vs-11:00 conflict beat. Hand-typed rehearsal messages get fresh Slack `ts` values, so `dedupe_key` collisions cannot happen (10-RESEARCH Pitfall 1). The reset controls accumulation, not collisions, so no upsert or unique-violation handling is added.

Output: `prisma/reset-demo.ts`, committed on `main` (D-01) and proven by a reset-twice smoke test. The D-06 double-post check needs hand posts in Slack, so it is the first human step of 10-02.

MVP note: the ROADMAP goal line for Phase 10 is not in user-story format, so no user story is invented here (run `/gsd mvp-phase 10` to add one).
</objective>
